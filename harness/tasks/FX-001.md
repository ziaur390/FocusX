# FX-001 · Build the first two-person accountability room

**Goal.** Two friends use separate signed-in browser sessions. Each enters a study goal, marks ready, sees a common countdown, reports their own outcome, and acknowledges the other's check-in.

**Scope.** Use the existing Next.js scaffold in `apps/web/` and Supabase migrations in `supabase/`. Read [session timer](../../docs/modules/M01-SESSION-ENGINE.md), [group sessions](../../docs/modules/M08-GROUP-SESSIONS.md), and [peer accountability](../../docs/modules/M11-STUDY-BUDDY.md). Use the [brand palette and typography](../../docs/BRAND-IDENTITY.md) for the basic room UI.

1. Check the SSH origin and open or reuse `feat/fx-001-accountability-room` from the reviewed baseline. Use the [GitHub workflow](../../docs/GITHUB-WORKFLOW.md). Install web dependencies at the repo root and include the generated `package-lock.json` with this task. Set up a dev Supabase environment with two test users and one outsider. Add the minimum authenticated access needed to reach a room.
2. Build private room creation with subject and duration, a join link or code, membership checks, and one goal plus ready state per student.
3. Start one round after two people are ready. Use a shared server deadline. Reload and reconnect to current state. Let either person leave without ending the remaining person's timer.
4. Implement self-owned **Completed**, **Partly completed**, or **Missed** outcomes and one mutual response per pair. Show the goals, outcomes, and pending or completed review actions to both members. Keep open check-ins visible.
5. Run plan, lint, typecheck, test, build, and browser checks. Commit the scoped feature branch and publish it when GitHub access is available. Prepare a draft PR with the latest commit, preview link, desktop/mobile evidence, and clearly marked pending checks. Zia uses the [review checklist](../../docs/REVIEW-FX-001.md) and merges after reviewing.

**Verify.** Run S1–S2, G1, and the ownership case from P3 in the [test matrix](../../docs/TEST-MATRIX.md). Open two distinct logged-in browser sessions. Check an outsider read, a duplicate check-in, a returning leaver, and that a peer can respond to but cannot edit another student's result. Record observed browser checks separately from any pending ones.
