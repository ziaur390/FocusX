## Ownership and recovery

| Record | Who can read | Who can change |
| --- | --- | --- |
| Room, members, rounds | Accepted room members only | Host creates and starts rounds; members set only their own goal and ready state before a live round |
| Goal and outcome | Round members | The member who owns it. RLS grants only select on outcomes; `submit_outcome` writes `auth.uid()` and never accepts another user id |
| Peer response | Round members | The assigned peer only, once, through `respond_to_peer`; retries are idempotent and the target's outcome is untouched |
| Invite preview | Anyone with the code | Not editable; shows subject, host, duration and member count |

Reload and reconnect rebuild the room from the server deadline and round rows. A live round is never duplicated: `start_round` rejects a second start while the previous deadline is ahead, and `(room_id, number)` is unique. Leaving sets `round_members.left_at`, keeps the remaining member's deadline, and leaves the leaver's check-in open until the 24-hour window closes. Outcome and response writes are keyed by round and member, so retries keep one row.
