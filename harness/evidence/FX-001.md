## Hardening pass

A second review found and fixed these user-visible defects; the browser checks above now cover them.

| Defect | Cause | Fix |
| --- | --- | --- |
| Waiting members never saw each other's ready state; the host's start button stayed disabled | The polling component only mounted after a round existed | The room polls while waiting, studying and checking in (15 s; 60 s once a round is closed) and refreshes when the tab becomes visible |
| The check-in form needed a manual reload | Same missing poll | The poll swaps in the server-rendered check-in form at the deadline |
| Countdown could jump or end early on a machine with a wrong clock | It used the client's absolute clock | It now uses the server timestamp plus monotonic elapsed time |
| A member joining mid-round saw a check-in form the server rejected | The form was gated on phase only | It is gated on membership of the frozen round roster |
| Uppercase usernames were blocked by the browser even though the server normalizes them | HTML pattern was lowercase-only | Pattern allows letters and numbers; normalization stays on the server |
| A duplicate username showed a raw database error | Sign-up error mapping only checked “already” | Maps duplicate and database errors to a readable message |
| A browser session for an account removed by a database reset hit a foreign-key error | The JWT outlived the account and the profile row was gone | `requireUser` checks the profile and sends the session to `/login?stale=1`; RPCs also return a clear error |
| Room list could show a stale round number after a start | No revalidation of `/rooms` | Start now revalidates the list |

## Ownership and recovery

| Record | Who can read | Who can change |
| --- | --- | --- |
| Room, members, rounds | Accepted room members only | Host creates and starts rounds; members set only their own goal and ready state before a live round |
| Goal and outcome | Round members | The member who owns it. RLS grants only select on outcomes; `submit_outcome` writes `auth.uid()` and never accepts another user id |
| Peer response | Round members | The assigned peer only, once, through `respond_to_peer`; retries are idempotent and the target's outcome is untouched |
| Invite preview | Anyone with the code | Not editable; shows subject, host, duration and member count |

Reload and reconnect rebuild the room from the server deadline and round rows; the open page polls every 15 seconds while work is pending and every 60 seconds once a round is closed. A live round is never duplicated: `start_round` rejects a second start while the previous deadline is ahead, and `(room_id, number)` is unique. Leaving sets `round_members.left_at`, keeps the remaining member's deadline, and leaves the leaver's check-in open until the 24-hour window closes. Outcome and response writes are keyed by round and member, so retries keep one row.
